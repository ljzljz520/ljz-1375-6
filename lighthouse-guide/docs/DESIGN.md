# 设计说明:登岛结论的组合规则与计算策略

## 1. 四条件组合规则(核心约束)

船班、天气、潮汐、场所开放是**四个相互独立的条件**:

| 情形 | 结论 |
|---|---|
| 四项均有确认数据,且存在共同有利时间窗口 | `LANDABLE`(给出具体窗口) |
| 船班全部取消/不衔接 | `NOT_LANDABLE` |
| 四项都有数据但无共同有利窗口 | `NOT_LANDABLE`(附原因) |
| **任一条件缺数据,或公告互相冲突** | **`UNKNOWN`(保留未知)** |

- **绝不只看其中一项就给出可登岛结论**:只有船班正常、或只有天气晴好,结论一律 `UNKNOWN`。
- 有利窗口 = 船班停留窗 ∩ 天气有利窗 ∩ 潮汐有利窗 ∩ 场所开放窗,再减去任一条件的不利区间
  (如观景台 09:00–12:00 临时关闭,会从窗口中削去该段)。
- 冲突判定:同一取代分组内最高代次生效;**同代次、不同来源、时间重叠且状态矛盾** → 登记
  `conflict_log`,该条件整体按未知处理,不偏向任何一方。
- 潮汐等窗口可跨日(23:00→次日 01:00),区间运算基于绝对时间戳,天然支持跨日求交。

## 2. 后台预计算 vs 请求时组合

系统同时提供两种计算路径(`GET /api/landing?date=…&mode=realtime|precomputed|compare`):

| 维度 | 后台预计算 `daily_plan` | 请求时实时组合 |
|---|---|---|
| 查询延迟 | O(1) 单行读取(实测 <1ms) | 4 张条件表扫描 + 区间求交(数 ms) |
| 结果新鲜度 | 取决于失效是否及时 | 永远最新 |
| 公告频率低(如每日 1 次) | **收益大**:缓存命中率高,预计算一次服务整天 | 浪费:每次重复算相同结果 |
| 公告频率高(台风天每小时更新) | **失效风暴**:每次导入都使当天缓存失效,预计算白做 | **更划算**:按需计算,不做无用功 |
| 一致性风险 | 可能读到 stale 结果(已标记,前端提示改走实时) | 无 |

### 缓存失效策略

- 公告导入时,按**适用日期(scope)+ 条目涉及日期**精确失效:`UPDATE daily_plan SET stale=1`,
  不整表清空,无关日期的预计算继续有效。
- 失效采用**标记而非删除**:读路径仍可返回 stale 结果并明确标注,由调用方决定接受或改走实时
  (compare 模式会报告 `consistent: false`)。
- 后台任务可定时重建 stale 行(演示中为手动触发 `POST /api/admin/precompute`)。

### 取舍结论

- **默认实时组合**:数据量小(单岛单日条件行数为个位数),实时计算毫秒级,正确性优先。
- **预计算用于高峰与弱网场景**:首页默认日期、离线包生成的批量日期,用预计算摊薄成本;
  公告越频繁,预计算价值越低,此时应缩短预计算调度周期或直接旁路。

## 3. 幂等与代次

- 公告表 `(source, kind, generation, payload_hash)` 唯一:完全重复的通知(如重复船班推送)幂等忽略。
- 条件表 `(target_key, generation)` 唯一:同键同代次重复推送不产生新行;同键更高代次取代旧行
  (临时取消即以此生效,且**路线按航次键 notify_key 引用船班**,取代后引用不悬空)。
- 每组条件保留最高代次参与求值,低代次仅留档审计。

## 4. 时间可信性

- 所有过期/失效/最后核对判断只使用**服务器时间**;客户端时钟(可快可慢)仅记录偏差并展示,
  不参与任何判定(`X-Client-Clock` 头仅用于测量 skew)。
- 条件时间一律归一化为 UTC 存储,展示时转换为岛区时区(+08:00)。

## 5. 历史资料与离线包

- 守塔人、灯塔历史为静态史料表,业务导入路径不触碰,临时取消不会使其失效。
- 离线包带 `expires_at` 与生成时代次;过期**或**公告代次更新即失效。任何情况下离线包/打印件
  都只是参考快照,**不得描述为现场安全或交通保证**,打印页强制附未确定事项与免责声明。
